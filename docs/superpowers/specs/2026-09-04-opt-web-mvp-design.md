# opt Web MVP 设计文档

## 1. 产品目的

`opt` 是一个记录“已经发生的微选择”的工具。用户只记录自己最终做出的行为，例如“躺在床上玩手机”，而不是同时记录当时存在的多个候选项。

软件不判断行为是否正确，不提供建议，也不定义统一标准。用户可以在记录当下或每日回顾时，将一条记录判断为绿色或红色；未作判断的记录保持中性。产品通过低摩擦记录和强烈但中立的视觉反馈，帮助用户留意日常微选择，并逐渐形成“让每个选择过脑”的觉察。

## 2. 第一版目标

第一版是可在 Windows 浏览器中直接运行的本地优先 Web MVP，必须满足：

- 无需账号、无需欢迎流程，打开即可记录。
- 新增一条记录只需输入一句话并按 Enter。
- 自动保存发生时间。
- 允许当下判断，也允许在指定时间集中回顾。
- 清晰呈现当天完整时间流和判断比例。
- 提供每日随心记录。
- 所有数据默认只保存在当前浏览器。
- 日常使用简洁、安静；集中回顾具有强烈、直接的视觉反馈。

第一版不包含账号、云同步、标签、搜索、智能建议、连续打卡、积分、跨设备同步或 Windows 原生安装包。

## 3. 产品原则

1. **只记录已发生的行为。** `opt` 不要求用户描述其他可能的选择。
2. **判断权属于用户。** 软件只保存红、绿或未判断状态，不解释其含义。
3. **记录不能成为负担。** 打开页面后输入焦点直接可用，记录流程不出现多字段表单。
4. **日常克制，回顾强烈。** 红绿颜色不在普通界面中泛滥，只在状态标记和回顾确认中承担明确含义。
5. **今天可调整，过去不可改写。** 当天数据允许编辑、删除、判断和撤销；跨过本地午夜后永久只读。
6. **不游戏化。** 不使用分数、连续天数、徽章、排名或带有褒贬意味的系统文案。

## 4. 信息架构

应用包含四个主要区域：

### 4.1 今天

应用默认且唯一的首页。顶部显示日期和单行输入区域，下方按发生时间排列当天记录，页面底部提供当天比例带和可折叠的“今日随记”。

### 4.2 回顾

沉浸式全屏流程，一次只展示一条尚未判断的当天记录。用户可从当天页面主动进入；到达设定时间后，页面出现安静的回顾提示，但不会强制进入。

### 4.3 过往

通过今天页面顶部的“下拉并短暂停顿”手势进入。历史记录先按日期折叠，展开后显示与当天一致的时间流，但所有内容完全只读。

### 4.4 设置

只包含每日回顾时间和浏览器通知开关。默认回顾时间为 21:30，用户可以修改或关闭提醒。

## 5. 核心交互

### 5.1 新增记录

- 页面打开后，输入区域可立即接收键盘输入。
- 用户输入一句话并按 Enter 即完成记录。
- 空白内容不能提交。
- 提交时记录当前本地时间，保存后清空输入内容并继续保持输入可用。
- 新记录默认状态为“未判断”。
- 不要求标签、原因、候选项或额外确认。

### 5.2 当天时间流

每条记录只显示：

- 发生时间；
- 行为文字；
- 小型状态色标。

未判断状态使用中性灰。向右拖动或按右方向键将记录判断为绿色；向左拖动或按左方向键将记录判断为红色。点击已判断的状态色标可恢复为未判断。键盘判断只作用于当前聚焦的记录。

编辑和删除入口默认隐藏，通过长按、右键或记录的键盘上下文操作进入。编辑只允许修改文字，不修改原始发生时间。删除后提供短暂的撤销入口，不使用阻断式确认弹窗。

### 5.3 全屏回顾

- 回顾只遍历当天尚未判断的记录。
- 每条记录独占屏幕，只显示行为文字和发生时间。
- 初始背景为接近黑色的中性色，不预示判断方向。
- 向右拖动时，背景随拖动进度逐渐呈现高饱和绿色。
- 向左拖动时，背景随拖动进度逐渐呈现强烈红色。
- 超过确认阈值并松手后，颜色完全充满屏幕并短暂停留，然后进入下一条。
- 未超过阈值时，记录回到中性位置且不保存判断。
- 桌面端支持鼠标拖动、触控板/触屏手势与左右方向键。
- 左上角始终提供明确的退出按钮，同时支持向下滑或按 Esc 退出。
- 退出时保留已经完成的判断，尚未判断的记录不发生变化。
- 全部完成时显示当天记录数以及绿、红、未判断数量，不显示系统评分。

### 5.4 历史入口与只读记录

- 当今天页面位于顶部时，继续向下拖动会逐渐露出“过往”入口。
- 保持约 500 毫秒后进入历史页，未达到停顿时间则自然回弹，避免普通滚动误触。
- 首次使用时只出现一次轻量提示，说明该手势；此后不重复打扰。
- 同时保留低调的“过往”文字入口，满足鼠标操作、可发现性和无障碍需求。
- 历史首页按日期折叠，每天仅显示日期以及绿、红、未判断数量概况。
- 展开某天后显示只读时间流，不允许编辑、删除、判断或撤销。
- 历史页提供明确的返回按钮，并支持向右滑、Esc 和浏览器后退返回今天。

### 5.5 日期锁定

日期边界使用设备的当前本地时区。进入新的一天后，前一天立即永久锁定。午夜时仍打开的页面应在日期变化后更新到新一天；前一天未判断的记录永久保持未判断，软件不会自动判断，也不允许补判。

### 5.6 今日随记

今天页面底部提供默认收起的“今日随记”。展开后是一个自由文本区域，内容自动保存。跨过午夜后，该随记与当天记录一起进入只读历史。

### 5.7 提醒与通知

- 默认回顾时间为本地时间 21:30。
- 到达时间且页面打开时，今天页面显示非阻断式回顾提示。
- 用户主动开启浏览器通知时，应用才请求通知权限。
- 用户拒绝权限、浏览器不支持通知或页面关闭导致通知无法送达时，不影响其他功能。
- 第一版明确接受普通网页无法保证后台通知送达的限制。

## 6. 视觉设计

视觉语言强调留白、准确层级和直接反馈，不复制任何现有产品的具体界面。

### 6.1 色彩

- 雾白背景：`#F4F4F1`
- 近黑正文：`#171816`
- 中性灰：用于未判断状态和辅助信息
- 判断绿：`#20C873`
- 判断红：`#F04444`
- 回顾中性背景：接近黑色

普通页面不使用大面积淡红或淡绿。高饱和红绿主要出现在全屏回顾的手势过程和确认瞬间，使颜色成为用户判断的视觉回响，而非软件的预先暗示。

### 6.2 字体与排版

使用无需联网下载的系统字体栈。Windows 优先采用 `Segoe UI Variable`，中文回退至微软雅黑等系统无衬线字体。品牌以小写 `opt.` 呈现。内容左对齐，限制文本行宽并使用充足留白。

### 6.3 时间流

时间流不是成组的装饰性卡片，而是一列清晰的记录行。左侧时间，中间为行为文字，右侧为小型状态色标。除必要的分隔、焦点和手势反馈外，不添加图标、标签、说明或永久菜单。

当天底部使用一条细长比例带表达绿、红和未判断占比，并同时提供文字数量，避免只依赖颜色传递信息。

### 6.4 动效与可访问性

- 动效只用于解释拖动方向、判断确认、历史入口和页面切换。
- 尊重 `prefers-reduced-motion`，在减少动态模式下取消位移和停留动画，但保留即时颜色与文字反馈。
- 所有核心操作均可使用键盘完成，并显示清晰的焦点状态。
- 红绿状态除颜色外还提供可读文字或无障碍标签，避免色觉差异造成信息丢失。
- 点击和拖动目标满足触控操作尺寸要求。

## 7. 数据模型与本地存储

第一版使用浏览器本地持久化存储，不访问远程服务。核心数据结构包括：

- `Choice`：唯一标识、行为文字、发生时间、判断状态、判断时间、创建时间、更新时间。
- `DayRecord`：本地日期、每日随记。
- `Settings`：回顾时间、提醒是否启用、通知偏好、历史手势提示是否已经展示、设备曾到达的最晚本地日期。

判断状态只有 `unjudged`、`green`、`red` 三种。统计由当天记录实时派生，不单独保存可产生不一致的分数。

应用启动时加载本地数据，并使用“当前本地日期”和“设备曾到达的最晚本地日期”中较晚的一项作为可编辑日期边界。这样，已进入历史的日期不会因用户回拨系统时钟而恢复编辑。写入失败时保留当前界面内容，并明确提示“未能保存到此浏览器”，避免假装保存成功。

第一版不承诺浏览器数据被手动清理后的恢复能力，也不提供导入导出；这两项作为后续版本候选能力。

## 8. 技术架构

采用 React、TypeScript 和 Vite 构建纯前端单页应用：

- 领域逻辑独立于界面组件，负责日期锁定、状态转换、回顾队列和统计计算。
- 存储模块提供版本化的本地读写接口，使未来迁移到 IndexedDB 或增加导出能力时无需重写界面。
- 手势模块统一鼠标、Pointer Events、键盘输入和阈值判断。
- 页面层只组合“今天”“回顾”“过往”“设置”四个区域。
- 不引入后端、路由服务、账户系统或状态管理框架。

首版可通过本地开发服务器运行，也可构建为静态文件并部署到任意静态托管环境。

## 9. 异常与边界情况

- 空白记录不可提交，输入内容仍留在输入区域。
- 连续快速提交必须生成不同标识并保持时间顺序。
- 页面在午夜保持打开时，应安全切换日期并锁定旧记录。
- 系统时区或时间发生变化时，以当前设备提供的本地日期重新计算可编辑日；已进入历史的日期不因时钟回拨而恢复编辑。
- 存储数据损坏时不得覆盖原始值；应用展示可理解的恢复提示并允许开始新的本地数据集。
- 通知权限被拒绝时不重复请求，设置中显示当前状态。
- 回顾过程中新增或删除记录时，队列按最新当天数据安全更新，不重复判断已完成项目。

## 10. 测试与验收

自动化测试覆盖：

- 新记录的默认状态、时间与排序；
- 红、绿、未判断之间的合法状态转换；
- 当天可编辑、历史日期只读；
- 午夜切换与本地日期边界；
- 回顾队列只包含当天未判断记录；
- 绿、红、未判断数量和比例计算；
- 每日随记和设置的保存与恢复；
- 本地存储写入失败的用户可见反馈；
- 拖动阈值、取消拖动和键盘判断。

浏览器交互验收覆盖：

- 页面打开即可输入并用 Enter 保存；
- 鼠标、触控与键盘均可完成判断；
- 全屏颜色反馈、退出操作和减少动态模式；
- 下拉停顿进入历史、备用文字入口和只读限制；
- Windows 常见桌面窗口、窄窗口与触屏尺寸；
- 通知关闭、允许、拒绝和不支持状态。

## 11. 第一版完成标准

当用户可以在 Windows 浏览器中完成“打开即记 → 当下或晚上判断 → 查看当天比例与随记 → 下拉查看不可修改的历史”完整闭环，且数据在刷新和重启浏览器后仍能恢复，第一版即达到可交付状态。
